**Decision:** scripts/distill-sweep.mjs gains --min-free-vram/--vram-poll (parks each chunk boundary via a nvidia-smi free-VRAM poll until a local merge model has enough headroom; no-op when nvidia-smi is unavailable) and --max-runtime-min (checked at chunk boundaries and while parked; stops the loop once a wall-clock deadline passes). scripts/nightly-distill.ps1 wraps the sweep for Windows Task Scheduler with a fixed budget (limit 300, gemma3:12b merge model, max 60 chunks, min-free-vram 4000, max-runtime-min 360), logs to .flow/distill-logs/ pruned at 30 days, and always exits 0 so a legitimate stop (time budget, GPU never freed) does not read as a task failure. It runs via `pwsh -NonInteractive -NoProfile -File` rather than an inline -Command, because Task Scheduler delivers a console control signal to powershell.exe when it hosts a long-running native process, killing the child with STATUS_CONTROL_C_EXIT. A new scripts/pre-sweep-snapshot.mjs is run immediately before starting a sweep: it VACUUM INTOs a WAL-consistent snapshot of nexus.db and records live/pending counts plus a rollback anchor timestamp (read from SQLite's own clock via `datetime('now')`, not the system clock) to .flow/distill-sweep-anchor.json, so the anchor always matches what distill actually stamps distilled_at with and pairs 1:1 with the snapshot it was taken alongside.

**Alternatives:** Let a resident-but-starved local merge model fail on its own: rejected, it does not fail cleanly — it times out slowly, so the sweep's existing consecutive-failure abort never trips and chunks limp along at a fraction of normal cluster yield instead of stopping or waiting. Run the nightly job as a plain scheduled PowerShell -Command: rejected, Task Scheduler's console-control-signal delivery kills the child distill-sweep.mjs process with STATUS_CONTROL_C_EXIT before it can finish a chunk. Take the pre-sweep snapshot and record the rollback anchor as two independent, separately-timed steps: rejected, a snapshot without a matching anchor leaves the operator guessing which --since to pass, and a stale anchor from an earlier session would make rollback-distill.mjs revert memories the capture hooks wrote in between and make audit-merges.mjs judge merges the sweep never made. Use the system clock for the anchor: rejected, it can drift from the timestamps distill itself writes via SQLite, which would silently misalign --since.

**Reason:** ADR-017 made the sweep resumable via the distilled_at cursor, which is what makes it safe to run unattended and stop mid-sweep for free. This closes the remaining gaps for running it that way on a schedule: a local merge model sharing the GPU with other work needs to wait rather than degrade silently, a nightly job needs to hand the machine back on a fixed schedule regardless of whether the sweep finished, Windows Task Scheduler has a specific console-signal failure mode for hosted native processes that a naive wrapper hits, and a sweep that mutates memories (supersedes originals) needs a cheap, exactly-matched restore point before it runs.
