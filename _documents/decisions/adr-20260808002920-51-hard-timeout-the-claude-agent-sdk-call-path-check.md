**Decision:** src/core/llm.ts callAgentSdk now races the async drain loop against a hard timer via Promise.race, in addition to calling ac.abort() at the configured timeout_ms (120000). Previously abort alone was insufficient: when the underlying claude CLI subprocess wedges, the claude-agent-sdk async iterator stops yielding but never rejects, so 'for await' waits forever regardless of the abort signal. The drain loop is extracted into a drain() closure; the orphaned promise gets a no-op .catch() to avoid an unhandled rejection when the race settles via the timer instead. callModel still degrades to '' on any failure, so every caller (reflector, distill, capture hooks) is unaffected by the change in mechanism. Companion fix in scripts/check-merge-model.mjs: a call that throws or times out was being caught, logged as FAIL, and continue'd WITHOUT incrementing any counter feeding the verdict, which tested only unsafe === 0 (fact-loss). A model that timed out on half its cases could exit 0 with 'VERDICT: safe for a distill sweep.' Added an errored counter and split the verdict into two independent disqualifiers: unsafe > 0 (correctness failure -- a lossy merge loses a fact because distill supersedes originals either way) and errored > 0 (viability failure -- distill-sweep.mjs aborts at 120s, shorter than this gate's own 180s call budget, so a model that times out here would return '' for its hardest clusters and grind through a sweep achieving almost nothing). Exit code is now unsafe === 0 && errored === 0. Files: src/core/llm.ts, src/core/llm.test.ts (new -- 3 vitest cases: normal passthrough, hang-returns-empty-within-budget, abort-still-signalled), scripts/check-merge-model.mjs.

**Alternatives:** Relying on abortController alone -- rejected, proven insufficient by a 2026-08-02 nexus_distill MCP call that sat wedged for 1800s (and an earlier ~6 hours) against the 120s budget it should have respected. Simply raising the timeout -- rejected, does not address the root cause (the SDK never rejects on a wedge, only a hard external timer can bound it). Collapsing errored into the existing unsafe counter -- rejected, they are different failure classes (a lossy merge destroys a fact permanently; a non-answering call destroys nothing but makes an unattended sweep grind uselessly) and conflating them would blur the verdict message an operator reads.

**Reason:** Root-caused from a real incident: a 2026-08-02 nexus_distill call stalled 1800s past its 120s budget because the async iterator never rejected on abort. The same blind spot existed one layer up in the merge-model gate: gemma3:12b's second evaluation run timed out on 3/6 cases (180s each) yet the gate's verdict logic never counted those failures, so it would have reported safe for a model that could not reliably answer. Both fixes close the same class of gap -- a call that never returns being silently treated as a non-event instead of a disqualifying failure.
