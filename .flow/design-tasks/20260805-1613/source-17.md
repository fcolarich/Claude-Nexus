# Reduced-dimension embeddings for storage/speed

**Source**: _documents/features/feature-20260805151847-77-reduced-dimension-embeddings-for-storagespeed.md

## Summary

This is a planned feature focused on reducing the dimensionality of embeddings generated by mxbai-embed-large to improve performance and reduce storage overhead. The feature is motivated by the desire to cut both vector storage size and search latency. The core proposal is to investigate whether mxbai-embed-large supports Matryoshka-style truncation—a technique where embeddings are generated at full dimension but then truncated to a smaller output dimension without meaningfully compromising recall quality. The feature is explicitly flagged as requiring research before implementation direction can be determined. A related proposal document exists in the LLM_Workflow_Optimization repository that likely contains additional technical exploration of the approach.

## Key facts

- Feature status: planned (not yet implemented)
- Primary motivation: reduce vector storage size and search latency
- Target embedding model: mxbai-embed-large
- Proposed technical approach: Matryoshka-style dimension truncation
- Marked as "needs-research" tag
- Has a linked proposal document for further reference

## Open questions

- Does mxbai-embed-large natively support Matryoshka-style truncation or reduced output dimensions?
- What is the recall-quality impact at various reduction levels?
- What reduction target (e.g., half, quarter of original dimension) would be practical?
- What threshold of recall loss is acceptable for the project's use cases?
- Are there alternative embedding models that already provide built-in dimension reduction capability?
